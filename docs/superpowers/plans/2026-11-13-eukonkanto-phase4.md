# Eukonkanto Phase 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a MariaDB database for the Wife-Carrying World Championship (Phase 3 schema with the approved changes), fill it with eukonkanto.fi data, and serve a Flask + React site at `http://localhost:5000` that implements all 32 Phase 1 functional requirements with raw, parameterised SQL.

**Architecture:**
- Rules live in the database: CHECK/UNIQUE/FK for single-row rules, `SIGNAL`-raising triggers for rules that read other tables, and views for derived values.
- Flask exposes a JSON API. Each repo function runs one raw SQL string through PyMySQL, and each response carries that SQL for the UI's "Show SQL" panel.
- A Vite/React SPA is built into `src/frontend/dist` and served by Flask.

**Tech Stack:** MariaDB 13.0.2 (Arch `mariadb` package), Python 3.14, Flask 3, PyMySQL 1.1, pytest 8, Node 26 / npm 12, Vite 6, React 18.3, react-router-dom 6.

**Spec:** `docs/superpowers/specs/2026-11-13-eukonkanto-phase4-design.md`

## Global Constraints

- Database name `eukonkanto_db`; test database `eukonkanto_test`. Tests derive the test scripts by replacing the literal `eukonkanto_db` in the SQL scripts.
- Charset `utf8mb4`, collation `utf8mb4_unicode_ci`, set on the database and in the connection. Names include ä, ö, õ and ’.
- Credentials come from env vars `DB_HOST` (default `localhost`), `DB_USER` (`phase4`), `DB_PASS` (`phase4`), `DB_NAME` (`eukonkanto_db`), in `src/config.py`.
- No ORM or query builder. Every query is a string constant with `%s` placeholders. User input never goes into SQL text.
- LIKE searches escape `%`, `_` and `\` in user input before wrapping it in `%...%`.
- No Python-side filtering, joining or aggregation of full tables. The work happens in SQL.
- API success: reads return `{"rows": [...], "sql": "..."}`; writes return `{"ok": true, "message": str, "sql": "...", **extra}`. API error: `{"error": str}` with status 400 (bad input), 404 (missing), or 409 (constraint/trigger).
- Trigger messages are user-facing English sentences, e.g. `Carrier must be at least 40 on race day for series M40`.
- Times are stored in seconds as `DECIMAL(7,2)`. They are displayed as `m:ss.d` when ≥ 60 s (1:04.4) and as `ss.cc` when < 60 s (33.77), matching the site.
- Ties share a rank (`RANK()`): the three 82.0 s finishers in 2026 Main are all rank 17.
- Brand colours: navy `#223c76`, cyan `#82ddf0`, orange `#f76a0c`.
- Rows invented rather than taken from the site carry a `-- GENERATED:` comment in `populate.sql`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Accented or apostrophe names** (Föhr, Jäntti, Sõbrad, Donncha O’Callaghan) must round-trip and be searchable. Test: Q1 search `föhr` finds Timo Föhr (Task 6).
2. **Search input with `%` or `_`** must be matched literally, not return every row. Test: `q=%` returns 0 persons (Task 6).
3. **Missing or non-numeric query params** (`year=abc`, no `series`) must return 400 with a message, not a 500. Test: `/api/results?year=abc` → 400 (Task 6).
4. **Two registrations racing for the same bib** must produce a readable 409, not a traceback. Test: duplicate bib → 409 "Bib number already used in this edition" (Task 8).
5. **Tied net times** must share a rank and have equal gaps. Test: 2026 Main bibs 41, 34 and 40 all have rank 17 (Task 3).

### Task 5: Backend core — config, db helpers, error mapping, app skeleton

**Files:**
- Create: `src/config.py`, `src/db.py`, `src/api/__init__.py`, `src/app.py`
- Test: `src/tests/test_api_core.py`

**Interfaces:**
- `config.get_db_config() -> dict` (host, user, password, database, charset="utf8mb4")
- `db.get_connection() -> pymysql.Connection` (DictCursor, autocommit=False)
- `db.query(sql: str, params: tuple = ()) -> list[dict]`: converts Decimal to float and date/datetime to ISO strings
- `db.transaction()`: a context manager yielding a cursor; commits on exit, rolls back and re-raises on exception
- `db.like(term: str) -> str`: escapes `\ % _`, returns `%term%`
- `api.respond(rows, *sqls) -> Response` builds `{"rows", "sql"}`; `api.done(message, *sqls, **extra)` builds `{"ok": True, ...}`
- `api.ApiError(status: int, message: str)`
- `api.parse_int(name, required=True)`, `parse_choice(name, allowed: set)`, `parse_str(name, max_len=100)` read from `request.args` or the JSON body and raise `ApiError(400, "<name> must be ...")`.
- Error handler mapping:
  - pymysql 1644 → 409 with the trigger text
  - 1062 → 409; the message names the bib when the key is `uq_reg_bib` (`Bib number already used in this edition`), otherwise `Duplicate value`
  - 1451 → 409 `Cannot delete: other records still refer to this one`
  - 1452 → 409 `Referenced record does not exist`
  - 4025 / 3819 → 409 `Value violates rule: <constraint name>`
  - 1048 → 400 `<column> is required`
  - Anything else → 500 `Database error`
- `app.create_app() -> Flask`; `app = create_app()`; `python app.py` serves on port 5000.
- `GET /api/health` → `{"rows": [{"db": "eukonkanto_test"}], "sql": "SELECT DATABASE() AS db"}`

**Interfaces:**

  ```json
  {"year": 2027, "series": "MAIN", "entry_type": "Pair", "team_name": null, "organisation": null,
   "countries": ["FIN"],
   "members": [{"role": "CARRIER_1", "person_id": 12} ,
               {"role": "CARRIED", "new": {"first_name": "...", "last_name": "...", "dob": "1995-04-02",
                 "gender": "Female", "email": "...", "citizenship": "FIN"}, "weight_kg": 47.0}]}
  ```
  `registrations.register(payload) -> dict(registration_id, bib_no, fee)` runs in one `db.transaction()`:
  1. INSERT any new PERSON + COMPETITOR + PERSON_CITIZENSHIP.
  2. INSERT ENTRY.
  3. INSERT PARTICIPATES_AS rows.
  4. INSERT REPRESENTS rows.
  5. `SELECT COALESCE(MAX(Bib_No),0)+1 FROM REGISTRATION WHERE Edition_Year=%s FOR UPDATE` → bib.
  6. INSERT REGISTRATION (`Registered_At=NOW()`, fee taken from RACE by `INSERT ... SELECT`, `Payment_Status='Paid'`).
  Payload validation (roles in the enum, ISO codes 3 letters, weight only on CARRIED) happens in Python → 400. Rule checks are left to the triggers.
- `POST /api/registrations/:id/cancel` → `{"refund": float}`. Runs `UPDATE REGISTRATION SET Cancelled_At=NOW(), Bib_No=NULL, Payment_Status='Refunded' WHERE Registration_ID=%s AND Cancelled_At IS NULL`, then reads Refund_EUR from `v_registration`. 0 affected rows → 404 or 409 "already cancelled".
- `GET /api/registrations/:id`: details for "Manage my registration" (registration, members, status, refund).
- `PATCH /api/entries/:id/roles/:role` with body `{"person_id": int}` or `{"new": {...}}` → U4.
- `DELETE /api/registrations/:id` → D1: in a transaction, `SELECT ... FOR UPDATE`; refuse (409) if cancelled, if any RESULT exists or if any AWARDED exists, with messages `Registration has results` / `Registration has awards` / `Registration is cancelled`; then DELETE.
- `GET /api/entries/unregistered` and `DELETE /api/entries/:id` → D2 (FK RESTRICT gives the 1451 → 409 refusal).
